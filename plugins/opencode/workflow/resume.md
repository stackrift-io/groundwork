**Merged after a pull.** `cleanup` restores the change folder to the delivered commit, so after a pull the `run.md` of a merged change shows the state it had when `deliver` ran. The `deliver` and `awaiting-delivery-approval` rows take this first only when the Log ends with `deliver: started`: `approve.md` step 5 item 7 writes it just before `deliver` commits, so it ends the committed `run.md`, and any later line means this delivery went on after it. Run `node "GW_HOME/scripts/gw.mjs" pr-status <change> --json`. `merged`: close the change as the `merged` case of the `awaiting-merge` row, and stop. `none` while `deliver.openPullRequest` is false: there is no pull request to check, so ask the user whether the change was merged by hand. Yes: run `node "GW_HOME/scripts/gw.mjs" cleanup <change> --force --json` and close it as for `merged`. No: go on with the row. Any other state, or exit 1: go on with the row.

## Resume with no change

`/groundwork resume` without a change checks every change that waits for a merge.

1. Run `node "GW_HOME/scripts/gw.mjs" status --json`. Its `open` list gives every open change with its `current` stage and `next` step.
2. For every change whose `current` is `awaiting-merge`, one at a time, run `node "GW_HOME/scripts/gw.mjs" pr-status <change> --json` and read only the fields the `awaiting-merge` row names. Close every `merged` one as that row says (`cleanup`, then `Current: done`). Start no feedback round here.
3. For every open change whose `current` is `deliver` or `awaiting-delivery-approval`, read its `run.md`. When the Log ends with `deliver: started`, it may have been merged and then pulled: run `node "GW_HOME/scripts/gw.mjs" pr-status <change> --json` and, when `state` is `merged`, close it as **Merged after a pull** says. Ask nothing about `none` here.
4. List the other open changes with their stage, the pull request state where you checked it, and their `next`. Stop. Next: `/groundwork resume <change>` for the change to continue.

Record every stage you run in the Stages table, as the orchestrator rules require.
